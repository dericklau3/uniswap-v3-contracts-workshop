# Contracts 教学化中文注释设计

## 目标

将 `contracts/` 下生产合约现有的中文注释改写得更详细、通俗，并结合 Uniswap 的实际业务流程帮助读者理解代码。覆盖 `v3-core`、`v3-periphery` 和 `swap-router`，排除 `test/` 与 `interfaces/`。

## 注释策略

采用分层教学：

- 核心业务流程详细解释业务目的、调用顺序、资金流、状态变化和关键边界。
- 数学与数据结构库解释输入输出、单位、定点数格式和直观例子，不机械复述每行代码。
- 简单辅助函数说明它在完整业务流程中的角色，避免注释比实现更难读。
- 保留必要的英文协议术语，例如 `tick`、`liquidity`、`swap`、`callback`、`TWAP`，首次出现时用中文解释。

## 重点路径

1. 池子生命周期：创建、初始化、添加/移除流动性、兑换、闪电贷和协议费。
2. LP 会计：`Tick`、`Position`、区间内手续费增长和跨 tick 流动性变化。
3. 价格与兑换数学：平方根价格、定点数、单步兑换和价格边界。
4. 预言机：观察点环形数组、累计值、插值和 TWAP。
5. 外围交互：回调校验、付款、路径编码、精确输入与精确输出。
6. 聚合路由：V2/V3 路由组合、滑点检查和 multicall 场景。

## 约束

- 不修改函数签名、状态变量、控制流、常量或运算表达式。
- 不调整 import 和继承关系。
- 保留 `contracts/v3-core/libraries/Oracle.sol` 中已有的未提交教学注释，并在其基础上统一风格。
- 不修改 `test/`、`interfaces/` 和生成产物。

## 验证

- 对比去除空白与注释后的源码，确认可执行 token 没有变化。
- 运行 `forge fmt --check`。
- 运行 `forge build`。
- 运行 `git diff --check`。
